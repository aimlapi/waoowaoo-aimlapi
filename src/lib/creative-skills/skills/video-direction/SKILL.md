# 视频导演与单镜头生成设计

## 作用

把已确认的剧情、Creative Direction、角色/场景/道具图片和声音身份，设计为一组可编辑的视频镜头。一个 `segment` 是一次 provider 生成，也必须是一个连续摄影镜头；不得在一个 segment 内要求切镜、快切、蒙太奇、分屏或多机位。剪辑发生在已生成 segment 之间，而不是让视频模型在一次生成里模拟成片剪辑。

## Skill 读取组合

`outputKind=video_prompt_set` 时必须在同一轮真实读取 `director-core`、`video-direction` 与 `quality-review`。三份知识共同生成一个 strict 结果，不产生并行 Prompt、隐藏镜头表或第二套审查结果。

## 先按成片思维设计，再拆为可生成镜头

先通读完整目标，建立整段成片的叙事弧和剪辑节奏，再划分镜头。不要逐段孤立续写。

每个镜头必须回答：

1. 这一镜为完整成片新增什么信息、动作结果或情绪变化；
2. 从上一镜的哪个可见/可听结果切入；
3. 本镜只完成哪个唯一动作节拍；
4. 以哪个已经完成、可由下一镜继承的状态结束；
5. 下一个切点为什么成立。

剪辑衔接优先使用可验证关系：主体位置、银幕方向、视线目标、动作结果、道具状态、图形关系或声音桥。相邻镜头至少在景别、机位角度、主体落位三项中改变两项，但不能为变化而重演上一镜动作。

## Strict 字段职责

- `key`：本次独立生成的稳定局部镜头标识。
- `durationSeconds`：只能从服务端给出的允许时长选择。
- `editRole`：该镜头对完整剪辑的唯一贡献。
- `entryState` / `exitState`：可观察的人物位置、朝向、视线、动作进度、道具、环境和声音状态；相邻镜头必须用同一个 `stateId` 完成交接。
- `incomingCut`：首镜为 `null`；后续每镜明确一个进入关系与可见/可听 handoff。
- `references`：只引用本镜真实使用的 source-material 标签，显式声明 `image` 或 `audio` 及用途。至少一张图片。不要输出 `@ImageN`、`@AudioN` 或数据库 ID；服务端会按这里的顺序确定性编号。
- `camera`：唯一景别、机位、主体落位、银幕方向、摄影机运动、镜头/景深、视线目标和构图。不能把资产板的白底、左右拼版、正面站姿、居中直视当作剧情构图。
- `action`：一个全局唯一 `beatId`，一次完整推进的可见动作，以及可选的逐字对白。同一节拍不能在另一镜用特写或换角度重看。
- `cutPoint`：本镜完成动作后的清楚切出落点。
- `sound`：本镜要原生生成的逐字对白、同步拟音、环境和必要声音桥。视频 segment 默认必须有可听原生声音；“无对白”不等于“无声音”。
- `prohibitions`：只放当前镜头特有的禁止项；通用禁令由服务端编译器统一追加。

Worker 不直接写最终 provider `prompt` 或 `referenceKeys`。服务端是唯一 Prompt writer，把上述契约确定性编译为与作品语言一致的分区提示词，并把 image/audio 分别编号为 `@ImageN` / `@AudioN`。

## 图片与声音引用

- 图片决定角色身份、场景结构和道具外观，不决定镜头构图、站姿、表情或视线。当前镜头必须重新给出真实剧情构图。
- 只引用本镜真正出现的项目资产图片。不要为了“可能有用”塞入无关素材。
- 声音引用只锁定角色音色；试听文字不是剧情对白。逐字剧情对白只写在 `action.dialogue`。
- 需要声音引用时仍必须同时引用图片；遵守服务端提供的图片和声音数量上限。
- Creative Direction 的 `crossMediaStyle` 与总体视觉政策约束视频；资产图专用白底、版式、灯光和材质规则不得进入剧情镜头。

## 单镜头设计

- 一个镜头只选择一种主要摄影机行为。锁定、推、拉、移、摇、升降或手持只能选最能服务当前节拍的一种。
- 有人物时写清主体落位、身体朝向和世内视线目标。除非题材明确打破第四面墙，视线不得与镜头交汇。
- 动作必须有可见起点、推进过程和完成落点，并能在分配时长内真实发生。不要用短动作循环填满长镜头。
- 人物移动时写清起点、路径与落点；下一镜从已经到达的新状态开始。
- 对白逐字保留，并安排在动作时间线上；动作、对白和环境声并行发生时不要把时长机械相加。
- 避免把剪辑术语渲染成画面。`incomingCut` 描述前后镜头的关系，本镜画面本身只描述已经成立的入口。

## 相邻镜头剪辑

- `hard_cut`：前一镜完成落点后直接进入不同景别/机位的新状态。
- `cut_on_action`：只能切在动作已经产生可继承结果的边界；两次独立生成之间不得从半个动作中间假装帧级无缝续接。
- `match_cut`：前一出口与后一入口存在明确形状、位置、颜色或运动结果对应。
- `sound_bridge`：前一声音持续或后一声音先行，但必须说明来源和停止边界。
- `motivated_reveal`：前一镜建立视线、声音或动作原因，后一镜展示其对象或结果。

禁止叠化、交叉溶解、淡入淡出和透明重叠。需要时间压缩或快切时，把每个 cut 设计成独立 segment，保留自己的 entry/action/exit，并由后续真实剪辑组合。

## 时长与完整流程

- `durationIntent.mode=fixed` 时，全部镜头时长之和必须等于用户明确要求的总时长。
- `durationIntent.mode=derive` 时，根据真实对白、动作、反应和必要停顿决定总时长，不向规划估时或模型最大时长凑数。
- 每个镜头只从 `productionContext.video.allowedSegmentDurationsSeconds` 选择。
- 一个动作无法在一次生成内完整结束时，应重新设计动作边界，而不是把半个动作切到两个独立生成。
- 第一镜建立完整入口；最后一镜给出能结束当前交付的出口。中间每对相邻镜头都必须完成 `exitState.stateId === entryState.stateId`。

## 自检

- 是否从整部成片出发设计，而非逐段孤立续写？
- 每个 segment 是否恰好一个连续镜头、一个动作 beat、一次 provider 生成？
- 每个镜头是否至少引用一张真实项目资产图片，并明确每个引用的用途？
- 图片身份是否被保留，同时资产板版式、白底、站姿和直视没有污染剧情构图？
- 相邻镜头是否至少改变两项构图维度，并通过位置、方向、视线、动作结果、道具或声音形成真实剪辑关系？
- `stateId` 是否逐对相接，后镜是否从下一个节拍开始而非重演？
- 对白是否逐字，角色音色是否引用正确，音轨是否包含可听的原生环境/拟音/对白？
- 是否没有内部切镜、快切组、蒙太奇、分屏、字幕、标题、水印、叠化或淡入淡出？

## 边界

本 Skill 只拥有镜头与剪辑设计。最终 provider Prompt、`@ImageN/@AudioN` 编号、Resource identity、能力校验、媒体提交、原生音轨实测和持久化由服务端权威模块负责。
