# 视觉风格开发

## 作用

把故事事实、用户要求与已有视觉上下文转化为一套可供图片和视频共同使用的视觉风格契约，并在需要时提供有实质差异的风格候选与预览方向。本 Skill 只负责视觉风格，不负责角色、场景、道具的具体资产设计。

## Style Bible 字段职责

- `rawUserStyle` 保存用户原始风格意图；它是来源事实，不是经过整理的生成约束。
- `styleSummary` 方便用户理解和比较视觉方向，不直接作为生成约束。
- `visualStyle` 是图片和视频共享的总体画面风格，必须把美术媒介、画面滤镜、总体质感和色彩基调整合成一段具体、可执行的描述。
- `assetImageStyle` 只供角色图、场景图、道具图和风格预览图等资产图片使用：
  - `lighting` 规定资产图片的风格化光线表达；
  - `texture` 规定资产图片的材质和细节质感；
  - `composition` 规定可复用资产图片的构图规则。
- 视频生成只消费 `visualStyle`，绝不继承 `assetImageStyle` 的灯光、材质细化或资产板构图。
- Style Bible 是视觉风格的唯一权威；资产设计只能消费它，不能根据单张参考图或单个资产重新定义项目风格。

## 视觉风格边界

- 视觉风格只决定美术媒介、画面滤镜、总体质感和色彩基调，不替导演决定叙事视角、表演、信息节奏、焦段、运镜、视频剪辑或声音。
- `visualStyle` 不写灯光、构图、焦段、运镜或声音；这些分别属于资产图片政策、导演、视频或声音设计。
- 区分跨图片与视频共享的总体视觉风格，以及只供资产图片使用的灯光、材质细节和构图规则。任何资产专用规则都不能被误写为跨媒体总体风格。
- 风格摘要方便人理解；真正用于生成的风格描述必须具体、可执行，不能只写“电影感”“高级”“梦幻”等抽象评价。
- 导演、影片、工作室、流派或年代引用应转写为可执行的媒介、材质、色彩、轮廓、细节密度和画面处理特征，不依赖受保护名称本身。
- 用户明确选择的风格和已确认项目 Style Bible 高于参考图片的原始画风。参考图可以提供身份、结构和材质事实，不能覆盖明确的美术方向。

## 风格候选

- 多个风格候选必须忠于同一剧情、角色、地点、道具和时间事实。
- 候选应在美术媒介、总体质感、色彩与设计语言上形成实质差异，而不是只做轻微调色。
- 每个候选都必须形成完整、自洽、可直接执行的 Style Bible，而不是标题加几条抽象形容词。
- 候选差异不能通过改变人物身份、场景事实、故事内容、年代或事件来制造。
- 用户已经明确要求某种风格时，候选只能探索该要求允许的合理范围，不能把明确要求降级为可选建议。

## 候选灵感词表（影视画风素材库适配版）

这份词表只用于扩展检索与组合空间，不是封闭枚举，也不是可以直接粘贴进 `visualStyle` 的标签包。用户可以提出词表外风格；明确的用户要求、已确认 Style Bible 和故事事实始终优先。

本词表只描述单帧画面中可以直接验证的视觉属性，不扩展到时序或声音维度。

适配后的字段公式是：`visualStyle = 主要媒介／制作表面 + 造型与设计语言 + 色彩关系 + 全局影像处理`；`assetImageStyle = 资产图风格化灯光 + 材质／细节表达 + 可复用资产构图`。年代、地域、世界观、类型和情绪只作为兼容约束与解释线索。

### 使用算法

1. 先锁定用户明确要求，以及输入中的剧情、角色、地点、道具、年代和世界规则；素材词不得改写这些事实。
2. 从下列词表筛选与事实兼容的媒介／设计语言、色彩／画面处理和资产图片政策。不要为了覆盖词表而强行选词。
3. 每个候选选择一个主要媒介和一个相容的设计语言，或一个明确的“媒介—设计语言”组合，再组合一组相容的色彩与画面处理，以及一组资产图灯光、材质和构图规则；禁止无层级地堆砌标签。
4. 三个候选至少在两个视觉维度上有实质差异，其中至少一个差异来自主要媒介或设计语言，不能只换颜色、亮度或情绪形容词。
5. 把选中的词转译成具体可执行的媒介、轮廓、材质、细节密度、色彩关系和画面处理；最终 Style Bible 不依赖裸标签、作品名、工作室名或受保护名称。
6. 光线与资产构图分别进入 `assetImageStyle.lighting` 和 `assetImageStyle.composition`。
7. 历史地域、类型、世界观和情绪词只作兼容筛选。仅当输入已有依据，且能无歧义落到单帧可见的媒介、造型、色彩、材质或全局影像处理时才采用；否则不进入 Style Bible。不得据标签新增年代、地域、建筑、技术、怪物或剧情设定。
8. 先归并同义或近义风格族，再生成候选。同一候选不重复堆叠同族词，三个候选也不能只靠同族的不同名称制造差异。常见同族包括：新现实主义／意大利新现实主义，诗意现实主义／法国诗意现实主义／伊朗诗意现实主义，魔幻现实主义／拉丁美洲魔幻现实主义，表现主义／德国表现主义，印象主义／法国印象派，日本侘寂／侘寂，公路电影美学／公路，拼贴／拼贴动画，水墨电影／水墨动画，油画／油画动画，像素／像素动画，阈限空间／阈限空间恐怖，空核／空核恐怖，以及 VHS／录像带电影／模拟恐怖。

## 风格预览

- 风格预览服务于比较视觉方向，不是新的剧情版本或资产事实来源。
- 预览画面必须使用对应候选的 `visualStyle` 与 `assetImageStyle`，不能混用其他候选的灯光、材质或构图。
- 预览可以选择关键故事画面展示风格适配性，但不得借预览改变人物身份、场景事实、道具状态或剧情内容。
- 预览中的偶然构图、姿态、光线细节和生成瑕疵不自动成为 Style Bible 或资产事实。

## 与资产设计的接口

- 本 Skill 决定跨媒体视觉政策和资产图片政策；角色、场景、道具的稳定外观与空间结构由资产设计负责。
- `assetImageStyle.lighting` 规定资产图共同使用的风格化灯光。场景自身真实存在的物理光源、位置、时间和照明条件属于场景事实，由资产设计提供。
- 最终资产图片提示词应把稳定资产事实与已确认 Style Bible 合成；不能把风格化灯光、滤镜或资产构图写回角色或地点的稳定身份描述。
- 参考图画风与 Style Bible 冲突时，保留参考图支持的身份、轮廓、结构和材质事实，并以 Style Bible 为最终画面风格。

## 自检

- `visualStyle` 是否只包含跨图片与视频共享的媒介、滤镜、总体质感和色彩？
- `assetImageStyle` 是否只包含资产图专用灯光、材质和构图？
- 是否把抽象风格名称转成了可执行视觉特征？
- 多个候选是否具有实质差异但仍忠于相同故事事实？
- 风格预览是否只用于比较，而没有创建新的剧情或资产事实？
- 是否避免让单张参考图重新定义已确认的项目风格？

## 边界

本 Skill 负责 Style Bible、风格候选与风格预览的专业方法。角色、场景、道具和参考资产的具体设计由资产设计 Skill 负责；导演、镜头、视频、声音与配乐由对应 Skill 负责。输出 Schema、候选数量、预览网格版式、图片画幅、provider 参数、真实人物安全策略和最终生成后缀由调用方与执行层定义。
