# 资产设计与生成提示词

## 作用

当 `outputKind=asset_prompt_set` 时，把服务端冻结的精确已确认结构化剧本与精确已采用 Style Bible，转化为剧本中全部 canonical 角色、场景和道具的可复用视觉设计。这两份冻结上游都是必需输入。本 Skill 汇总现有中英文资产 Prompt 的有效规则并使用同一基线，避免不同语言得到不同设计纪律。它只产出资产设计与生成提示词，不直接生成图片或写入项目。

## 权威输入与资产身份

- `productionContext.asset.screenplay` 是服务端冻结的精确已确认结构化剧本；`productionContext.asset.style` 是服务端冻结的精确已采用 Style Bible。它们不是可选参考，也不能被 `goal`、`sourceMaterials`、参考图或模型推断替换。
- 只有 `productionContext.asset.screenplay.snapshot.canonicalRegistries.characters`、`locations` 和 `props` 构成唯一、穷尽的资产名单。`facts`、剧本正文和 scenes 都不是第二份名单。
- 为每个 character 输出一次且仅一次 `canonicalEntity={kind:"character",entityId:characterId}`；为每个 location 输出 `canonicalEntity={kind:"location",entityId:locationId}`；为每个 prop 输出 `canonicalEntity={kind:"prop",entityId:propId}`。不得新增、遗漏、重复、合并或改写任何 identity。
- 不得扫描故事梳概、剧本正文、对白、scenes 或 Stage 05/05A 来推断、补充或删除资产。Stage 05/05A 的使用场次、实体状态变化，以及其他 facts/scenes 只能帮助设计已登记实体的可见特征与连续性要求，不能改变资产数量或身份。
- 顶层 `source.screenplayRevision` 必须逐字段回显 `productionContext.asset.screenplay.source` 的 `resourceId`、`revisionId`、`fingerprint`、`bindingVersion` 和 `schemaId`；`source.styleRevision` 必须逐字段回显 `productionContext.asset.style.source` 的同一组身份。不得猜测“最新版”、替换 revision 或自行生成来源标识。

## 风格消费边界

- 冻结的已采用 Style Bible 是视觉风格的唯一权威，必须精确、只读地消费其跨媒体 `visualStyle` 与资产图专用 `assetImageStyle.lighting/texture`。不得根据单张参考图或单个资产重新定义项目风格，不得修改、补写或输出另一份 Style Bible。
- 始终把不含风格的稳定资产身份写入 `stableDescription`，再把稳定身份与该精确 Style Bible 合成为执行 policy 之前的创意 `generationPrompt`；不能用该生成 Prompt 反向改写稳定身份或上游风格。
- 角色稳定身份描述不混入艺术风格、滤镜和光影；这些由最终生图提示词统一追加。
- 场景基础描述保存真实空间结构、材质与物理光源条件；风格化灯光和材质处理只在最终生图提示词中与 Style Bible 合成。
- 资产图固定版式由执行层的唯一 asset-image format policy 按资产类型追加并裁决；`generationPrompt` 不得另写相冲突的版式、背景或主体数量要求。
- 这套固定版式只约束资产图，不拥有、覆盖或约束视频构图。视频构图、景别、机位、运镜和剪辑仍完全属于导演与视频模块。
- 精确已采用 Style Bible 高于参考图画风。参考图用于身份与结构，不能覆盖已确认的美术风格；忽略原图偶然色调、光线、模糊、噪点和瑕疵。

## 固定资产图格式与执行边界

- 人物资产是一张固定 4:3 横向图片，画面左右各半：左半为同一人物的脸部特写，右半为从头到脚完整可见的全身；使用纯白背景，只能出现这个人物，不能出现场景、道具或其他人物。
- 场景资产是一张固定 4:3 横向图片，是从正前方完整展示空间的全景环境图，不得拆成多视图；不能出现人物、松散家具或作为独立资产主体的道具。墙、地面、门窗、楼梯等构成场景本身的固定结构与内建要素可以保留。
- 道具资产是一张固定 4:3 横向图片，只展示一个摆正且完整可见的道具，它必须方向明确、居中且完整无遮挡，使用纯白背景；不能出现人物、其他道具或场景。
- 以上是资产类型契约，不是供模型选择的风格或构图候选。Skill 只保证设计内容与契约兼容；执行 policy 是 4:3 画幅、精确版式和最终 suffix 的唯一 writer，`generationPrompt` 不得复制这些执行指令。

## 角色设计

### 人类角色的可见信息

- 明确性别呈现和具体年龄感。
- 描述脸型和可见五官特征、眼睛形状与大小，但不描述眼睛颜色。
- 描述头发颜色、长度、发型与发质。
- 描述身高感、体态、肩宽、腰线和整体轮廓。
- 皮肤只写质感和可见标记，如粗糙、光滑、雀斑、胎记、疤痕或纹身；禁止肤色、唇色、脸色和其他身体部位颜色。
- 服装写清款式、年代、材质、配色、结构和细节；鞋子是完整人物设计的必要部分，必须写款式、材质和颜色。
- 只添加能加强身份和复用性的可穿戴配饰，例如眼镜、耳饰、项链、手表或戒指。
- 服装、发型、鞋履和配饰必须符合故事年代与社会背景。

### 非人类角色

- 动物、神话生物、非人形生物或明确的风格化形象不强套人类外貌模板。
- 描述从角色名或物种名开始，围绕形态、轮廓、表面、关键器官、服饰和核心辨识特征展开。
- 修改时保留其身份锚点，只改变用户明确要求的部分。

### 角色描述纪律

- 角色资产描述只写稳定外貌，不写表情、姿态、动作、背景、环境、手持剧情道具或故事性句子。
- 不用“或”“可能”“也许”“大概”等不确定词；每个视觉选择明确具体。
- 不写“气场强大”“成熟稳重的气息”等无法直接看见的抽象气质。若需要表达身份能量，应转译为可见轮廓、服装、材质和配饰。
- 以原文明确外貌为最高优先级，但仍遵守身体颜色限制和当前安全边界。
- 在不过度锁死的前提下保留合理生成空间。除非输入要求，不规定每根发丝、每个色块或每件配饰。

## 参考角色图

- 从参考图提取脸部结构、发型、体型、服装结构和可穿戴配饰等稳定身份特征。
- 参考图只展示局部身体时，根据可见服装与角色身份合理补齐下装、鞋履、手臂和手部；补全部分必须与已见部分协调。
- 图像反推仍不得描述肤色、眼睛颜色、表情、动作、背景和姿势。
- 反推分析可以给出由画面直接支持的整体造型或气质关键词，帮助理解身份方向；进入最终生图描述时，必须把这些关键词转译成可见的轮廓、服装、材质和配饰，不能留下无法视觉化的抽象判断。
- 转成资产图时，保持正常美观的人体比例、完整服装鞋履和主要可穿戴配饰，表情自然平静，身份锚点稳定。不得要求风格背景、多视图、动作分解或语境样本；最终图片必须清晰锐利、细节丰富并达到专业生产质量，不复制参考图的模糊、噪点或瑕疵。

## 角色候选

- 候选只用于同一 canonical character 的内部设计比较；最终必须选定一个方向，只写入该 `canonicalEntity` 唯一的 `assets` entry。
- 候选必须是同一角色身份的不同设计方向，不是不同角色。
- 可以分别强化：身份与轮廓忠实度、服装/材质/年代质感、角色能量与跨场次身份参考可用性。
- 候选差异应清楚但仍共享角色核心身份；不要通过改变年龄、物种、关系或剧情事实制造假差异。
- 选角、服装、色彩、材质和氛围必须与精确已采用 Style Bible 兼容。

## 场景设计

- 从明确的场景名称或空间身份开始，把泛称具体化为稳定可控的真实空间，而不是停留在“教室”“办公室”等标签。
- 忠实保留用户指定的核心场景身份、固定结构、内建要素、材质、时代感和空间关系，不能替换为更熟悉但无关的场景类型。
- 写清建筑与空间结构：墙、地面、天花、门窗、边界、开口、尺度和纵深。
- 材质、颜色和表面状态具体可见；可加入属于建筑或空间本体的使用痕迹，避免用独立道具陈设制造场景身份。
- 明确前景、中景、背景或近处、中部、远处的层次，保持完整全景和可理解的空间边界，不生成局部裁切或含糊背景。
- 设置至少三个稳定、清晰可见的结构锚点；锚点必须来自墙、地面、门窗、楼梯或其他固定结构与内建要素，不能用独立道具填充画面。
- 新建最终场景生图描述时，光线应包含真实来源、位置、时间和对空间的可见效果。修改作为项目事实保存的基础地点描述时，只保留物理光源与照明条件，不写由 Style Bible 统一追加的戏剧化光影效果；最终生图提示词再把基础地点事实与资产图片风格合成。任何资产专用灯光规则都不能被误写为跨媒体总体风格。
- 场景资产始终不加入人物，也不加入作为独立资产主体的道具；不能以“场景天然拥挤”为由增加匿名人群或松散道具陈设。
- 场景资产应是可复用的环境建立画面，不是某个瞬间的叙事分镜。不要出现对白、字幕、解释文字、水印、标注、箭头或 Logo。
- 场景世界中自然存在的文字只有在属于场景固定结构或内建要素时保留，例如固定招牌或门牌；保持次要自然，避免随机乱码和漂浮文字。

## 场景候选

- 候选只用于同一 canonical location 的内部设计比较；最终必须选定一个方向，只写入该 `canonicalEntity` 唯一的 `assets` entry。
- 从该 canonical location 的使用场次中选择最能揭示其空间身份、利于后续视觉复用的设计依据，不机械复述第一次出现，也不得把它替换为另一 location。
- 基准方向忠实还原空间身份、固定结构、结构锚点、材质和光线。
- 叙事核心方向强化同一 location 承载冲突、揭示、反转、持续压力或情绪转折的方式，通过建筑、负空间、固定结构、动机光源、色彩和材质体现张力，而不是写解释或改换地点。
- 电影美术质感方向根据年代、类型、阶层感、情绪温度和潜台词，强化空间结构、表面、使用痕迹、实景光源、空气、反光和阴影；不能靠人物、独立家具或道具陈设增加美术密度。
- 各候选仍必须是空场景、完整环境和可复用参考，不能通过加入不同剧情事实制造差异。

## 道具设计

- 只描述道具本体的静态视觉信息：主体结构、轮廓、数量关系、材质、颜色、表面处理、纹样、装饰和磨损。
- 不写用途、剧情、角色动作、人物、手部、桌面、房间、背景、镜头或氛围光影。
- 设计正文只保留单一道具本体，并与执行 policy 的固定道具资产图格式兼容。
- 参考图可提供轮廓、结构、材质、纹样与配色，但不能引入参考图中的偶然背景或人物。

## 修改已有资产

- 修改不得改变或新建 `canonicalEntity`；仍然必须对三张 canonical registry 中的每个实体恰好输出一次。
- 先识别用户要求改变的具体视觉特征，再准确替换或补充相关部分。
- 保留所有未被修改的原有身份、结构、材质、颜色、装饰和风格事实。
- 有参考图片时只吸收与修改目标相关的关键视觉特征，不让参考图覆盖用户已确认内容或 Style Bible。
- 修改后重新检查整段描述的流畅性、一致性、时代感和资产类型边界。
- 场景修改如果增加或删除关键锚点，必须同步更新空间结构、层次和落位空间；不能退化为泛场景。

## 自检

- 顶层 screenplay/style source refs 是否与服务端冻结身份逐字段一致？
- `assets` 是否只包含 canonicalRegistries.characters/locations/props，并且每个实体通过精确 `canonicalEntity` 恰好出现一次？
- 是否精确、只读地服从已采用 Style Bible，并清楚区分跨媒体 `visualStyle` 与资产图专用 `assetImageStyle.lighting/texture`？
- 角色是否稳定、完整、年代一致、鞋履明确，并排除了身体颜色、动作、背景、不确定词和抽象气质？
- 非人类角色是否按真实形态处理而非套用人类模板？
- 场景是否忠实、正前方完整、结构清楚、锚点稳定，并排除了人物与独立道具资产？
- 道具是否只包含静态本体信息？
- 候选是否产生有意义差异但不改变身份和剧情事实？
- 修改是否保留所有未被要求改变的特征？

## 边界

本 Skill 负责 canonical 角色、场景和道具的视觉设计，参考图只提供已登记实体的身份与结构依据，候选只是同一实体的内部比较。Style Bible、风格候选与风格预览由视觉风格 Skill 负责；本 Skill 只读消费精确已采用 revision。执行层唯一 asset-image format policy 负责 4:3 图片画幅、固定资产图精确版式与最终图片提示词后缀；本 Skill 不复制 suffix，不生成新资产 identity，也不触碰导演、镜头、镜头运动、视频构图、剪辑、对白演绎、声音或配乐。
