# 生产资产筛选与稳定身份

## 作用

从一个精确 `screenplay` Revision 中筛选后续图片和视频真正需要复用的角色、地点与道具，并为每项资产写一份不含风格的稳定身份。正式 `asset_manifest` 是项目生产资产范围的唯一事实。

本 Skill 不生成图片，不写 provider Prompt，不设计候选，不修改已有资产，不写数据库 identity，也不决定镜头、构图、动作、表演、灯光或声音。最终资产图片 Prompt 由服务端把这里的 `stableDescription` 与已采纳 Creative Direction 确定性编译。

## 输入权威

- 必须完整读取唯一、精确的 screenplay source material；不得根据摘要、最近资源、历史消息或记忆补写资产。
- 服务端可能注入已采纳 Creative Direction。它只帮助判断哪些视觉身份需要跨媒体保持，不得把艺术风格、灯光、滤镜、构图或渲染媒介写入 `stableDescription`。
- 用户明确指定的资产范围优先，但不得编造剧本中不存在且用户也没有要求的新角色、地点或道具。
- 不回传原文 excerpt、offset、数据库 ID 或逐项证据字符串。精确 Revision 与 Lineage 已由服务端记录。

## 资产筛选

一项实体只有同时满足以下条件才进入 manifest：

1. 在交付画面中真实出现，或承载一个可见动作/信息；
2. 其人物身份、空间结构或物件外观需要跨两个以上镜头保持一致，或者后续必须作为独立媒体参考；
3. 不能由另一项已选资产完整代表而不损失关键连续性。

因此：

- 只在对白、旁白或背景设定里被提及但不会出现的实体不登记。
- 无身份群众、普通装饰、瞬时背景物和不影响连续性的消耗品不登记。
- 同一实体的景别、机位、表情、动作、光线和临时状态不是新资产。
- 同一地点中结构明显不同、各自承载动作且必须独立引用的空间可以拆分；只是一闪而过或无需独立连续性的区域不拆分。
- 没有实体通过门槛时允许 `assets=[]`，并在 `overview` 解释；不得为了非空虚构资产。

## Canonical identity

- `kind` 只允许 `character`、`location`、`prop`。
- `canonicalName` 使用剧本或用户最稳定、最明确的称呼。
- `aliases` 只收录输入中真实出现、确实指向同一实体的其他称呼；不得收录描述性短语或未来可能的昵称。
- 同一实体只能登记一次。不同名字指向同一实体时合并为 canonical name + aliases。
- 不得把同名不同实体错误合并；必要时在 canonical name 中加入剧本已经支持的区分信息。
- `manifestAssetId` 由服务端根据稳定 identity 编译；Worker 不输出或猜测。

## `stableDescription` 总原则

`stableDescription` 只保存跨镜头必须稳定、可以从输入确定、且与渲染风格无关的可见事实。

必须：

- 用确定句，不使用“或、可能、也许、大概、可选择”等不确定表达；
- 具体到足以让后续生成保持同一身份，但不锁死每个像素；
- 保留时代、地域、阶层、功能和物理结构所要求的事实；
- 把抽象气质翻译为可见轮廓、服装、材质、磨损或结构；
- 只描述静态、可复用身份。

禁止写入：

- 摄影、真人、写实、二维、三维、黏土、定格、插画等渲染媒介；
- “电影感、高级、高清、专业成片、概念图、资产板”等输出质量或用途词；
- 色彩分级、滤镜、镜头、景别、构图、灯光、景深、背景和画幅；
- 表情、姿势、动作、对白、剧情瞬间、情绪表演或相机视线；
- negative prompt、reference requirements、continuity requirements 或最终 generation prompt。

## 角色稳定身份

角色只写跨镜头需要保持的人物本体和长期造型：

- 年龄感、性别呈现、身高感、体态、肩宽和整体轮廓；
- 脸型、可见五官特征、眼睛形状与颜色；
- 头发颜色、长度、发型和发质；
- 肤色、肤质，以及真实存在的疤痕、胎记、纹身等标记；
- 长期服装的年代、款式、材质、配色、结构、鞋履和可穿戴配饰；
- 非人类角色的物种、形态、轮廓、表面、关键器官、服饰和核心辨识特征。

不要写当前表情、身体姿势、手持剧情道具、所处地点或临时损伤，除非该变化已经成为后续持续不变的新身份且用户明确要求本次 manifest 从该状态开始。

## 地点稳定身份

地点写可复用空间本体：

- 建筑/空间类型、尺度、边界和纵深；
- 墙、地面、天花、门窗、楼梯、开口和固定结构之间的关系；
- 物理材质、颜色、表面状态和时代性使用痕迹；
- 至少三个能帮助后续人物落位与方向保持的稳定空间锚点；
- 剧本明确的固定自然/人工光源位置，只作为空间事实，不写戏剧化照明效果。

不要写某一镜的机位、构图、天气特效、人物动作、临时道具摆放或情绪氛围。松散家具和独立物件只有在属于地点固定结构、不可分离时才进入地点描述。

## 道具稳定身份

道具只写本体：

- 数量关系、尺寸感、轮廓、主体结构和开合/连接方式；
- 材质、颜色、表面处理、纹样、装饰和长期磨损；
- 能区分它与同类普通物件的稳定标记；
- 剧本要求保持的文字内容仅在它是关键身份事实且后续必须可读时记录。

不要写谁拿着它、它放在哪里、如何运动、当前是否被使用、镜头如何拍摄或周围是什么场景。

## Creative Direction 消费边界

完整 Direction 可以帮助判断“什么必须成为跨媒体身份”，但不能污染稳定描述：

- `visual.renderMedium`、`realismLevel`、`crossMediaStyle`、`assetImageStyle` 与 `assetPolicy` 由服务端资产 Prompt 编译器消费；
- Worker 不复述这些字段，不把“真人/插画/黏土/定格”等写进 stable identity；
- 没有 Direction 时仍可完成资产清单；不得临时发明项目级风格；
- 参考图若作为 source material 提供，只能贡献稳定身份或结构事实，不能覆盖用户/Direction 的风格政策。

## 输出纪律

每个 asset 只输出：

- `kind`
- `canonicalName`
- `aliases`
- `stableDescription`

整个结果还包含 `kind=asset_manifest`、`overview`、`assumptions` 和 `warnings`。`assumptions` 只记录无法从输入确认但为了完成资产身份不得不采用的有限假设；`warnings` 只记录会实质影响后续生产的输入冲突或缺失。

## 自检

- 每项资产是否真的会出现并需要独立连续性？
- 是否漏掉了承载关键动作、揭示或结局的角色、地点或道具？
- 是否把同一实体按镜头、动作、光线或状态重复登记？
- 名称与 aliases 是否来自输入且没有歧义？
- stableDescription 是否足以锁定身份，同时完全没有媒介、写实度、风格、灯光、构图、姿势、表情和剧情瞬间？
- 是否没有 generation prompt、negative prompt、reference requirements、continuity requirements、excerpt、offset、候选或数据库 ID？

## 边界

本 Skill 只拥有生产资产范围与无风格稳定身份。Creative Direction 拥有项目呈现政策；服务端 asset-image compiler 拥有最终图片 Prompt；图片 Operation/Task 拥有媒体执行；Binding service 拥有项目资产与生成图片的关系。
