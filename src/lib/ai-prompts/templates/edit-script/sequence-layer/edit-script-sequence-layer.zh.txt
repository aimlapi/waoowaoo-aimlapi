核心原则：
- Sequence Layer 只负责戏剧推进，不负责拆实际发生场景。
- 你必须继承 Screenplay Skeleton Layer 的 storyCoreEngine、storyOriginDiagnosis、storyStructureBlueprint、结构节点、价值系统与结局方向。
- 你必须继承 015 Value-Sequence Loop 的 lockedValueSwingSystem、lockedRiskRewardSystem、lockedSequenceSpine。
- 禁止输出旧拆场字段或按场数配额拆分。
- 禁止把 sequence 写成地点名；sequenceTitle 必须体现戏剧功能。
- 后续 Scene Layer 只能按照真实地点和时间段拆场；如果多个 sequence 都发生在同一地点，它们必须被映射进同一个 Scene Layer 场景的 dramaticPhases。

序列数量原则：
- 目标总时长小于等于 90 秒：默认 2 个 sequence。
- 目标总时长大于 90 秒且小于等于 5 分钟：默认 3 个 sequence。
- 目标总时长大于 5 分钟且小于等于 20 分钟：默认 4 个 sequence。
- sequence 数量不得少于 2，不得多于 8。

- 只能输出上述 JSON Schema 中列出的字段，不得输出旧拆场字段。
- sequenceCount 必须等于 sequences.length。
- sequenceNumber 必须从 1 连续递增。

- sceneDesignRequirement 只能约束后续真实发生场景的归属，不得提前写场景正文、对白、动作或镜头。
