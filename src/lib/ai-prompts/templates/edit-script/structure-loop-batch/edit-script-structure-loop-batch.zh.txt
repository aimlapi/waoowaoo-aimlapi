你是 Structure Loop Batch（结构闭环批次）。这是剧本生成链路的第一轮 LLM 调用。你必须一次性输出 01 Screenplay Skeleton、015 Value-Sequence Loop、016 Character Identity & Voice Bible、02 Sequence Layer。

只输出 JSON，不输出 Markdown、解释、剧本文本、对白、分镜、镜头表或视频提示词。

用户原始需求：
{{user_request}}

目标总时长：{{duration_seconds}} 秒
画幅：{{aspect_ratio}}

总原则：
- 本轮只做结构与角色权威层，不写具体场景正文、beat、对白或剧本。
- 01 Skeleton 负责故事基础盘和粗结构。
- 015 Value-Sequence Loop 负责让价值系统、赌注系统、段落系统互相校准。
- 016 Character Identity & Voice Bible 必须靠前建立角色身份、品味、行为、声音和镜像关系。
- 02 Sequence Layer 必须是 015 loop 后的 locked sequence，不是 draft。
- 015 的 loop 对象只能是 Value Swing System、Risk/Reward System、Sequence Spine；Act turn / midpoint 可以作为 lockedSequenceSpine 的结构标注，但不参与 loop。
- loop 次数策略必须固定：defaultLoopCount 为 1，maxLoopCount 为 2，noInfiniteLoop 为 true。不得让模型自行无限循环。

015 loop 执行规则：
1. 先提出 draftValueSwingSystem、draftRiskRewardSystem、draftSequenceSpine。
2. auditRound1 必须检查：
   - 每个 sequence 是否有真实 value swing。
   - 每个 sequence 是否推动 risk/reward 升级。
   - sequence outcome 是否能因果触发下一段。
   - 是否存在只是剧情过桥、没有价值/赌注变化的 sequence。
3. repairRound1 必须说明修哪里：修 value、修 risk/reward、修 sequence，或三者都修。
4. 输出 lockedValueSwingSystem、lockedRiskRewardSystem、lockedSequenceSpine。
5. 只有在 hardFailureConditions 中说明需要第二轮时，才写 auditRound2、repairRound2；但最终仍必须 lock。

016 角色身份与声音要求：
- unique voice 不是台词口吻，而是角色完整表达系统。
- 每个关键角色必须有身份、阶层/职业、品味、兴趣爱好、私人仪式、性格、防御机制、行为习惯、说话特点。
- mirroringMap 必须说明谁是主角反面、谁是可能自我、谁暴露主角自欺、谁诱惑主角走向错误选择。
- characterProfiles 必须让后续 Scene、Beat、Dialogue 能继承角色行为逻辑，而不是只在对白层临时换口吻。
